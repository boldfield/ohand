# Tauri 2 iOS management-shell probe: build and validation

Probe for task P06. It checks whether Tauri 2 is a viable shell for the
management and settings screens. Native capture stays outside the webview
(P07 probes the handoff, P10 records the decision).

## Result

The probe builds from a clean checkout, installs and launches on an iOS
simulator, and completes one native round-trip. CI job `tauri-probe` in
`.github/workflows/ios.yml` enforces this on every pull request.

Evidence, run 37707826863 on commit 8a730c16 (all steps green; artifact
`tauri-probe-evidence`, kept 7 days):

- Runner macOS 15.7.9, Xcode 16.4 (16F6), iOS simulator SDK 18.5, rustc/cargo 1.99.0, Node 22, tauri-cli 2.12.1 (`toolchain.txt`).
- Simulator iPhone 16, iOS 18.5 (`simulator.txt`).
- `tauri ios build --debug --target aarch64-sim` produced `src-tauri/gen/apple/build/arm64-sim/ohand-tauri-probe.app` (`build.log`).
- `simctl launch` returned a live PID for `com.boldfield.ohand.tauri-probe` (`roundtrip.log`).
- `roundtrip.json`, written by Rust from the text the webview rendered: `{"status": "Success", "rendered_result": "Echo from Rust: Hello from Tauri"}`.
- `screenshot.png` of the running app.

## Pinned toolchain

- Tauri crates: `tauri =2.12.1`, `tauri-build =2.7.1`; the full resolved set (`tauri-utils 2.10.1`, `tauri-codegen`/`tauri-macros 2.7.1`, ...) is fixed by the committed `src-tauri/Cargo.lock`. An earlier attempt pinned only `tauri =2.4.1`, which resolved an incompatible `tauri-utils` and failed to compile; pin the whole family through the lockfile and regenerate it as one set.
- CLI: `@tauri-apps/cli =2.12.1` from the committed `package-lock.json` (`npm ci`), run as `npx tauri`. There is no `cargo install tauri-cli` step. The webview uses the injected `window.__TAURI__` global (`app.withGlobalTauri`), so `@tauri-apps/api` is not a dependency.
- Rust 1.99.0 from the repository `rust-toolchain.toml`, plus `rustup target add aarch64-apple-ios-sim`.
- Xcode 16.4 on `macos-15`, matching `ios.yml`.
- `probes/tauri/src-tauri` is excluded from the root Cargo workspace, so `make check` and `make test` do not build it.

## Reproduce locally (macOS)

```bash
cd probes/tauri
rustup target add aarch64-apple-ios-sim
npm ci
npx tauri ios init --ci                       # generates src-tauri/gen/apple (git-ignored)
npx tauri ios build --ci --debug --target aarch64-sim
xcrun simctl boot "iPhone 16"                 # any available iPhone simulator
xcrun simctl install booted src-tauri/gen/apple/build/arm64-sim/ohand-tauri-probe.app
xcrun simctl launch booted com.boldfield.ohand.tauri-probe
```

The app runs the echo on load. To see the result, take a screenshot
(`xcrun simctl io booted screenshot out.png`) or read
`roundtrip.json` in the app data container
(`xcrun simctl get_app_container booted com.boldfield.ohand.tauri-probe data`).
The Echo button repeats the call.

## What CI asserts

1. Webview assets contain no credential-like strings, `http(s)://` URLs, `fetch(` or `XMLHttpRequest`; `cargo metadata --locked` resolves.
2. The build produces an `.app` bundle.
3. After launch, `roundtrip.json` appears in the app container within 60 seconds and equals exactly `Success` / `Echo from Rust: Hello from Tauri`. JavaScript calls `echo_message`, renders the returned string, then passes the rendered DOM text to `record_roundtrip`, so the file proves the value reached the UI.
4. The app process is still alive, and a non-empty screenshot is captured. Any failure fails the job.

## Design notes

- Frontend is static, committed in `probes/tauri/dist` (single copy, no build step). No local server and no remote scripts; CSP is `default-src 'self'; connect-src ipc: http://ipc.localhost; style-src 'self' 'unsafe-inline'; script-src 'self'`.
- The only commands are `echo_message` and `record_roundtrip`. No product logic lives in the web UI, and no provider key or secret is passed into JavaScript; production credentials stay in native/Rust code and cross the boundary only as opaque references.
- Custom commands are callable by the main window without extra capability files because no app-level command ACL manifest is defined. A production shell should define one.

## Known limitations and incompatibilities

- `src-tauri/gen/apple` is generated by `tauri ios init` on every CI run and not committed. The generator needs macOS/Xcode, so it cannot be produced or checked on Linux workers. Linux checks (`make check`) therefore do not prove this probe builds; only the macOS job does.
- Desktop (Linux) `cargo check` of the probe needs `webkit2gtk-4.1`, which Linux workers lack; the Rust unit test for the echo helper has no Linux job.
- Builds are unsigned debug simulator builds. Device builds, signing and provisioning are P08/P09 and are not claimed here.
- The icon set is generated from a synthetic placeholder image (`npx tauri icon`); no brand assets.
- This proves a launch and one IPC round-trip on iOS 18.5 only. It says nothing about capture, background behavior, memory, or App Store acceptance.
