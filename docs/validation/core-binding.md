# Rust-to-Swift boundary validation (P01)

P01 proves one small, real call boundary between the Rust core and Swift before product code commits to it. It is a probe, not the production bridge: B01/B01a own `core/src/ffi/`, `ios/OhAndCoreBridge/` and `tools/bindings/` and reuse what is established here.

## Decision

Hand-written `extern "C"` functions with a header generated by [cbindgen](https://github.com/mozilla/cbindgen), imported into Swift through a bridging header. A general RPC layer was rejected as out of scope; an object-model generator (UniFFI) was not needed to answer the questions below and adds a Swift-side generation step that the first bridge does not need. If B01 finds this surface too narrow, that is a B01 decision with this probe as its baseline.

## What exists

| Path | Role |
| --- | --- |
| `core/bindings/src/lib.rs` | The entire C ABI. |
| `core/bindings/src/probe.rs` | Boundary-independent logic: request parsing, size bound, cancellation checkpoints, calls into the real `ohand-core` capture store. |
| `core/bindings/include/ohand_bindings.h` | Generated header (C, not C++). `core/bindings/tests/header_drift.rs` fails `make test` if it is stale or leaks C++ or unrelated core items. Regenerate with `OHAND_UPDATE_BINDINGS_HEADER=1 cargo test -p ohand-bindings --test header_drift`. |
| `core/bindings/build-ios.sh` | Xcode run-script phase: builds `libohand_bindings.a` for the SDK and architectures being built and merges them with `lipo`. |
| `ios/BridgeProbe/Sources/Boundary/` | Swift wrapper (`OhandBoundary.swift`), bridging header and the launch self-check. |
| `ios/BridgeProbe/Tests/BoundaryTests.swift` | XCTest suite that calls the real Rust library; target `BridgeProbeTests`, run by the `OhAndTests` scheme. |

`core/bindings` is a workspace member (a one-line addition to the root `Cargo.toml` plus the resulting `Cargo.lock` entries) and the Xcode wiring is confined to the `BridgeProbe` and `BridgeProbeTests` targets in `ios/project.yml`. Both are shared files whose other editors (F02, F05) are ancestors of P01 in the dependency graph, so the edits are serialized; P01 cannot build or run on a simulator without them. Nothing under `core/src/` or `ios/OhAndCoreBridge/` is changed.

## Contract demonstrated

- **Data**: requests and responses are UTF-8 JSON byte buffers with explicit lengths. NUL bytes inside text never truncate it, and no function depends on NUL termination. The capture-shaped value is validated by, and stored through, the real `ohand_core::store::captures` API in an in-memory database.
- **Normalized failures**: every call returns `OhandResult { status, data, len }`. Status 0 is success; 1-5 are the contract classes `transient`, `permanent`, `unauthorized`, `cancelled`, `unsupported` (the probe emits `permanent` and `cancelled`). The payload is JSON `{class, code, message}` with fixed messages that never echo caller content.
- **Bounds**: requests longer than `OHAND_MAX_REQUEST_BYTES` (1 MiB, counted in bytes) are rejected as `request_too_large` from the length alone, before any caller memory is read.
- **Ownership**: Rust allocates each result buffer; Swift copies the bytes and releases the buffer exactly once with `ohand_result_free`, which clears the struct so a second free is harmless. Stores and cancel tokens are opaque handles released with their `_free` function. Null is accepted by every release function. `ohand_bindings_live_allocations` counts live Rust-owned objects so tests can assert that every success, failure, cancelled and panic path returns the count to its baseline.
- **Lifetime**: the Swift `ProbeStore` wrapper takes a lock around every call and around `close()`, so a handle is never freed while Rust is using it; calls after `close()` fail with `store_closed`.
- **Cancellation**: calls are synchronous and cooperative. Cancellation is observed at three points: call entry, after validation, and immediately before the commit. A call that reports `cancelled` has changed nothing (the open transaction is dropped, which rolls it back). Once the commit has happened the call succeeds, and a late `cancel()` never undoes a committed capture. `cancel()` is safe from any thread and after the call finished. In-flight native work is not interrupted; that is the contract for effects that outlive their owner (cancelled work produces no mutation).
- **Panics**: every exported function that can run caller-influenced code converts panics into the `internal` failure instead of unwinding across `extern "C"`.
- **Unsafe surface**: functions that dereference caller pointers are `unsafe extern "C"` with documented safety requirements; null required arguments return `null_argument`.

## Evidence

Linux (`make check`, `make test`, run by `core.yml`):

- `core/bindings/tests/boundary.rs` drives the exported C functions exactly as Swift does: ASCII and Unicode round trip (combining marks, RTL controls, ZWJ emoji, interior NUL), idempotent retry, conflicting ID reuse keeping the original words, invalid UTF-8, malformed and unknown-field JSON, missing and mutually absent fields, null pointers, exact size bound (limit accepted, limit+1 rejected, multibyte counted in bytes, bogus pointer with oversized length never dereferenced), cancellation before the call, at each internal checkpoint (via the internal hook) and after completion, concurrent cancellation being all-or-nothing, live-allocation accounting, store isolation, and panic containment.
- `core/bindings/tests/header_drift.rs` checks the committed header against cbindgen output.
- The generated header was also compiled as C11 with `cc -Wall` and linked against the staticlib in a small C program on Linux.

macOS (`.github/workflows/ios.yml`, simulator job):

- `xcodebuild test -scheme OhAndTests` builds `libohand_bindings.a` for the simulator through the run-script phase, links it into `BridgeProbeTests` and runs `BoundaryTests`, which repeat the Rust scenarios through the Swift wrapper plus Swift-specific ownership, lifetime-under-concurrency and thread-safety cases.
- `BridgeProbe` is then built and launched on the simulator. At launch it saves and reads back a Unicode capture through the real core and checks that invalid UTF-8 is rejected; a mismatch calls `fatalError`, so a broken boundary fails the smoke test, which requires the process to stay alive.

The run for the exact submitted commit, found with `gh run list --workflow ios.yml --commit <sha>`, is linked from the pull request together with the downloaded `ios-evidence` artifact (`OhAndTests.log` containing `** TEST SUCCEEDED **` and the `BoundaryTests` cases, and `smoke.log` ending with `Smoke test passed`). This document does not claim a result for any commit; the run is the evidence.

## Findings for B01

- A header generated by cbindgen with `language = C` is imported through a bridging header rather than a modulemap, which keeps the probe free of a framework or module-map target. The C symbols live in the app and test targets that link the static library. A module-based import was not evaluated.
- The Rust toolchain is pinned by `rust-toolchain.toml`; the iOS targets are installed by the run-script phase with `rustup target add`, and the Cargo build runs under `env -i` so Xcode's compiler variables do not leak into the bundled SQLite C build.
- The simulator slice needs `aarch64-apple-ios-sim` (and `x86_64-apple-ios` when Xcode builds an Intel simulator slice); there is no `x86_64-apple-ios-sim` Rust target.

## Not covered

- Physical device builds (`aarch64-apple-ios`) are scripted but not exercised here.
- Asynchronous Swift call styles and interrupting a call that is already running inside SQLite are not part of this probe.
